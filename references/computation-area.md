## 1. 顶栏（Top Bar）

✅ 截图实证（#5 #6 #7 #8 #9 #10 #11 #13 #15 #23）

答题界面顶栏自左至右三段：

```
[< 返回]   [标题]   [进度 x/n]  [✏ 笔]  [计时 0:H:M]
```

| 元素 | 位置 | 文案/格式 | 实证 |
|---|---|---|---|
| 返回箭头 `<` | 最左 | 返回上一级（设置页） | ✅ 全部答题截图 |
| 标题 | 返回箭头右侧 | 题型名 或 `行测小助手`（见下） | ✅ |
| 进度 | 标题右侧偏左 | `x/n`，如 `1/10`、`1/5` | ✅ |
| 笔图标 ✏ | 进度右侧 | 蓝色笔形图标 | ✅ |
| 计时 | 最右 | `0:H:M` 格式，如 `0:0:1` | ✅ |

### 标题的取值规律（⏳ 待确认）

✅ 观察到标题在不同题型下取值不一致，未找到稳定规律：
- 显示**题型名**的：`增量比大小`(#8)、`基期比大小`(#9)、`分数比大小`(#14)、`分数计算(…`(#11#12)、`基期比重`(#13)
- 显示**`行测小助手`**的：估算前期量(#5)、估算增长量(#6)、百化分(#7)、年均增长率(#10)、年平均量(#15)、基础计算(#23)

🟡 推断：可能标题取"进入答题前所在分组的标题"，或原版本身不一致。**实现建议**：统一显示当前题型名（更清晰），不必复刻此不一致。

### 计时格式 ✅

格式 `0:H:M`（固定一位"0:"前缀 + 分 + 秒），秒数不补零。实证值：`0:0:0`、`0:0:1`、`0:0:30`、`0:2:52`。
- 🟡 推断：这是"会话累计秒数"的简写，`0:` 是小时位恒为 0。超过 1 小时是否变 `1:xx:xx` ⏳ 待确认。
- 计时从**进入第一题即开始**（#5 第一题已显示 `0:0:1`）。
- ⏳ 是否可暂停：截图未显示暂停按钮，推断**无暂停**（速算训练强调连续作答）。

### 笔图标 ✏ 的作用（⏳ 待确认）

✅ 蓝色笔图标在所有答题截图的进度与计时之间出现。截图为静态，无法确认点击行为。
- 🟡 推断：可能用于"标记/笔记当前题"或"切换触控笔模式"。实现时可先做占位，行为待定。

## 2. 题目区（Question Area）

✅ 题目区位于顶栏下方、键盘上方，居中显示。呈现方式因题型而异，分三类：

### 2.1 直接公式型 ✅

算式以大字号居中显示，后接 `≈` 或 `=` 与答案输入位。

| 题型 | 算式样例 | 上下文 | 截图 |
|---|---|---|---|
| 估算前期量 | `9738/1.102≈` | `现期: 9738, 增长率: 10.2%` | #5 |
| 估算增长量 | `求增长量：？` | `现期:9385 增长率:28.4%` | #6 |
| 百化分 | `1/11 ≈ %` | — | #7 |
| 分数计算(分子＜分母) | `632/924 ≈ 0.` | — | #11 |
| 分数计算(分子＞分母) | `977/524 ≈` | — | #12 |
| 基期比重 | `(323/371)×(1.02/1.217)≈` | `A: 323, 21.7%; B: 371, 2.0%` | #13 |
| 基础计算 | `61+84=` | — | #23 |

要点：
- ✅ 分数用真分数排版（横线分上下），非 `632/924` 文本式（#11#12#13）。实现用 KaTeX。
- ✅ 答案输入位紧跟 `≈`/`=` 之后，**内联**而非独立输入框（#11 显示 `≈ 0.` 后跟光标）。
- ✅ 分子＜分母时预填 `0.`（#11 `632/924 ≈ 0.`），因为结果必 <1；分子＞分母时不预填（#12）。
- ✅ 上下文数据（现期/增长率/A/B 值）以较小字号显示在算式下方（#5#6#13）。

### 2.2 图表呈现型 ✅

✅ 年均增长率(#10)与年平均量(#15)使用**柱状图**呈现数据，对应设置页"生成文字图表"模式。

实证图表要素（#10 成交量 2012-2017）：
- 绿色竖柱，柱顶标注数值（如 `29.18万`）
- Y 轴刻度（`0万` 到 `60万`，等距）
- X 轴年份（`2012`…`2017`）
- 图例：绿色方块 + `成交量`

提问以文字行呈现：`求2012~2017的年均增长率: %`(#10)、`求2012~2016的年平均成交量: 万`(#15)。

🟡 推断：图表为程序随机生成的"文字图表"（非真实真题），数值与年份由生成器产出。实现时用 ECharts 渲染柱状图，数值标在柱顶。

### 2.3 比较题型 ✅

✅ 两个算式左右并排，中间绿色 `?`。详见 §11。

## 3. 时间标准（合格/良好/优秀）

✅ 截图实证（#23 基础计算答题）

**时间标准直接显示在答题界面题目区下方**，一行三段：

```
合格：28s  良好：22s  优秀：18s
```

- ✅ 这是 `basic_addsub` × `10题` 的标准，与 references/levels.md「时间标准」种子值完全吻合（28/22/18）。
- ✅ 标准按"题型 × 题量"查 `time_standards` 表得出（见 data-model.md）。
- 🟡 推断：资料分析类答题截图(#5#7#11#13)未显示此行——可能资料分析题型不显示标准行，或截图恰好未截到。**实现建议**：所有题型统一显示标准行（透明可见目标，激励作用），查不到时降级用题型默认/全局默认。

> why 显示在答题屏：速算训练的核心是"又快又准"，把目标秒数摆在眼前能让用户即时感知节奏，而非答完才知道是否达标。

### 标准的查表逻辑 ✅（见 levels.md「时间标准」）

`题型 + 题量` → 查 `time_standards` 表取 `pass_s/good_s/excellent_s`；查不到用题型默认；全无用全局默认。设置页可编辑。

## 5. 数字键盘（Numpad）— 核心复刻对象

✅ 截图实证：**基础计算**与**资料分析**使用**两套不同键盘布局**。这是对原 spec 的重要修正。

### 5.1 基础计算键盘（有 ±）✅（#23）

```
┌─────────────────────────────┐
│  [拖拽手柄] 上下拖调大小 左右拖调位置 双击恢复 │
├──────┬──────┬──────┤
│  ±   │ 清空 │ 退格 │   ← 行1：符号/清空/退格
├──────┼──────┼──────┤
│  1   │  2   │  3   │   ← 行2
├──────┼──────┼──────┤
│  4   │  5   │  6   │   ← 行3
├──────┼──────┼──────┤
│  7   │  8   │  9   │   ← 行4
├──────┼──────┼──────┤
│  .   │  0   │ 确定 │   ← 行5：小数点/0/确定(绿)
└──────┴──────┴──────┘
```

- ✅ 行1 有 `±`（正负号切换）键。
- ✅ `重开` 作为**独立粉色圆形按钮**位于键盘上方/侧边，不在网格内（#23）。
- ✅ `确定` 在网格右下，绿色。
- ✅ 键盘顶部有拖拽说明栏：`上下拖调大小 左右拖调位置 双击恢复` + 拖拽手柄图标。

### 5.2 资料分析键盘（无 ±，重开入网格）✅（#5#6#7#11#13）

```
┌──────┬──────┬──────┐
│ 重开 │ 清空 │ 退格 │   ← 行1：重开/清空/退格（无±）
├──────┼──────┼──────┤
│  1   │  2   │  3   │   ← 行2
├──────┼──────┼──────┤
│  4   │  5   │  6   │   ← 行3
├──────┼──────┼──────┤
│  7   │  8   │  9   │   ← 行4
├──────┼──────┼──────┤
│  .   │  0   │ 确定 │   ← 行5：小数点/0/确定(绿)
└──────┴──────┴──────┘
```

- ✅ 行1 为 `重开/清空/退格`，**无 ± 键**。
- ✅ 负号"需要时自动生成"（#6 明文 `需要负号时会自动生成`）——即资料分析答案若为负，系统自动加负号，用户无需手动输入。
- ✅ `重开` 在网格左上（非独立按钮）。

> why 两套布局：资料分析的答案几乎不会是用户主动输入的负数（增长率/比重等语境负值罕见且系统可判定），省掉 ± 键腾出位置给 `重开`；基础计算的减法结果可能为负（若题型允许），需用户手动切号。实现时两套布局都做，按题型切换。

### 5.3 键盘可拖拽 ✅（#23）

✅ 明文拖拽说明：`上下拖调大小 左右拖调位置 双击恢复`
- 上下拖动 → 调整键盘大小（高度）
- 左右拖动 → 调整键盘位置
- 双击 → 恢复默认大小/位置

这与 levels.md L1「可拖拽：上下调高、左右调位、双击恢复」一致——✅ 截图证实。

### 5.4 唤起原生键盘 ✅（#23）

✅ 键盘区域有提示文案 `点击这里唤起原生键盘`。
- 🟡 推断：点击后调出系统原生键盘（对应物理键盘/系统输入法），实现"双输入"的另一路径。
- 本版决策（SPEC §2 #8）：双输入——屏幕数字键盘 + 物理键盘，两路径均可用。

### 5.5 翻题箭头 ✅（#23）

✅ 键盘底部左右角各有 `<-` `->` 箭头。
- 🟡 推断：用于手动上一题/下一题导航（而非只能顺序作答）。

### 5.6 物理键盘映射 🟡（spec 已定，截图未直接显示）

见 levels.md L1 物理键盘映射表（0-9/./- 输入，Backspace 退格，Enter 确定，Escape 重开，Delete 清空）。比较题额外映射见 §11。

### 5.7 键盘布局顺序开关 ✅（#3#19）

✅ 设置页有"键盘布局"开关，选项 `正序/倒序/乱序`（#19 基础计算设置页实证）。
- 🟡 推断：控制数字键 1-9 的排列顺序。`正序`=123456789 标准排列；`倒序`/`乱序` 打乱以增加认知负荷（防肌肉记忆）。
- ✅ #3 资料分析设置页也有此开关（显示 `正序`）。

> why 乱序：速算训练要的是"心算能力"而非"按键肌肉记忆"，打乱键位迫使大脑参与定位，提升真实计算反应力。

## 10. 比较题特殊交互 ✅（#8#9#14）

✅ 比较题（增量比大小/基期比大小/分数比大小）**无数字键盘**，改用 4 大按钮：

```
┌──────────────┐  ┌──────────────┐
│    大于      │  │    小于      │   ← 选择行
│   (绿色)     │  │   (橙色)     │
└──────────────┘  └──────────────┘
┌──────────────┐  ┌──────────────┐
│    重开      │  │    确定      │   ← 控制行
│ (薄荷绿)     │  │   (灰色)     │
└──────────────┘  └──────────────┘
```

- ✅ 题目区：两算式左右并排，中间**绿色 `?`**。
  - #8 `482/252 × 25.2%  ?  303/301 × 30.1%`
  - #9 `909/1.261  ?  1046/1.315`
  - #14 `749/732  ?  769/819`
- ✅ 按钮：`大于`(绿) / `小于`(橙) / `重开`(薄荷绿) / `确定`(灰)。
- ✅ 流程：选 大于/小于 → 高亮选中 → 点 确定 提交 → 判分。
- ✅ `重开` 重置当前题（重新出题或清空选择）。
- 🟡 物理键盘映射（spec 已定）：`>` 或 `1`=大于，`<` 或 `2`=小于，Enter=确定。

> why 绿/橙配色：大于=正向=绿（强调色），小于=负向=橙（警示色），符合 design-system.md 的 `--app-color-warning` 橙色用于"小于"。
